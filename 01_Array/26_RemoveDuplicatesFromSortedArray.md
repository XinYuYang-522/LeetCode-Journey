# LeetCode 26. 删除有序数组中的重复项

### 1. 一句话核心思路
* 利用数组有序、重复元素必然相邻的性质，让 `fast` 扫描相邻元素，让 `slow` 指向下一个唯一元素应该写入的位置。

### 2. 循环不变量
* 题目保证 `nums.length >= 1`，因此第一个元素必然需要保留，初始化 `slow = 1`。
* 每轮循环开始时，区间 `[0, slow)` 保存了已经扫描区域中的全部唯一元素。
* 当 `nums[fast] != nums[fast - 1]` 时，`nums[fast]` 是一个新的唯一元素，将其写入 `nums[slow]` 并移动 `slow`。
* 遍历结束后，`slow` 等于唯一元素的数量，也是有效区间 `[0, slow)` 的长度。

### 3. Java 实现

```java
class Solution {
    /**
     * 原地删除非严格递增数组中的重复元素。
     *
     * 前置条件：nums.length >= 1。
     * 时间复杂度：O(n)
     * 空间复杂度：O(1)
     */
    public int removeDuplicates(int[] nums) {
        int slow = 1;

        // 有序数组中的重复元素必然相邻。
        for (int fast = 1; fast < nums.length; fast++) {
            if (nums[fast] != nums[fast - 1]) {
                nums[slow] = nums[fast];
                slow++;
            }
        }

        return slow;
    }
}
```

### 4. 复杂度分析
* **时间复杂度：** $O(n)$。`fast` 从下标 `1` 开始扫描数组一次。
* **空间复杂度：** $O(1)$。去重结果直接覆盖到原数组的前部。

### 5. 边界与易错点
* **单元素数组：** 循环不执行，直接返回 `1`。
* **全部重复：** `slow` 始终为 `1`，只保留第一个元素。
* **没有重复：** 每个元素都会写回对应位置，最终返回原数组长度。
* **只检查有效区间：** 题目只验证 `nums[0, slow)`，不需要清理后面的旧元素。
* **空数组属于题目约束之外：** 当前写法对空数组会返回 `1`。若将方法复用为通用 API，应先增加 `nums.length == 0` 的保护分支。

### 6. 面试官考察点
* 能否利用“有序”这一前提，将去重转化为相邻元素比较。
* 能否讲清 `slow` 表示有效长度，而不是最后一个有效下标。
* 能否区分题目保证的输入约束与生产代码需要主动防御的非法输入。
